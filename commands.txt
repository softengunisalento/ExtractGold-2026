COMMANDS

Notes
- Run every command from the repository root unless stated otherwise.
- Replace the values in <angle brackets>.
- Flags of llama-server change between builds: check them with `./build/bin/llama-server --help`.

0. Build the frozen replay set (once, before the sessions)

	python build_replay_set.py prepare --min-turni 10 --lingua en
	python build_replay_set.py tokenize
	python build_replay_set.py sweep --min-turni 10 --solo-informatica --n-per-strato <N> --dettaglio 4000
	python build_replay_set.py select --min-turni 10 --min-tokeni 4000 --solo-informatica --n-per-strato <N>
	python build_replay_set.py verify

	- Choose --min-tokeni from `sweep`: it reports, per threshold, the surviving
	  conversations, the strata reaching N and the retained p50/p90 prompt tokens,
	  and writes dataset_cache/sweep.csv. `--dettaglio` lists the strata below N.
	- `--min-tokeni` (4000 in the examples) is the threshold being validated, not a
	  measured optimum: freeze it only after the sweep and the professor's review.
	- `--solo-informatica` keeps code plus conversations that discuss a CS/IT topic
	  without pasting code (first user message, two technical signals or one plus
	  an explicit explain/implement/debug request, non-CS domains excluded).
	  At 4000 it leaves 563 conversations on 18 strata; `--solo-coding`, the
	  stricter code-only option, leaves 523; without either filter, 3,081.
	  At 4000, `--n-per-strato 5` gives 80 conversations / 1,669 turns and
	  `--n-per-strato 6` gives 94 / 1,928.
	- The frozen set uses `--n-per-strato 0`: all eligible conversations
	  (563, 9,804 turns); `5` and `6` above are trial samples.

	- `--lingua en` is the default, so English-only applies even if the flag is omitted;
	  the detector runs on all three sources. The first run downloads fastText lid.176
	  (~131 MB) into dataset_cache/models/. `--tutte-le-lingue` is for trials only.
	- The frozen set uses 10 turns and 4000 tokens; re-run `select` to test other thresholds.
	- Changing only the thresholds means re-running `select`; `prepare` is needed again only
	  if `--min-turni` changes.
	- Every model must use the same `-c` (32768 in step 3); `select --contesto-runtime`
	  must match it.
	- The output in replay_set/ is frozen evidence: do not overwrite it after the sessions start.

1. Activate the virtual environment
	source venv/bin/activate

2. Start MongoDB (skip it if it already runs as a service)
	sudo systemctl start mongod

3. Start llama-server, ONE model at a time
	
	./llama.cpp/build/bin/llama-server -m ../models/<folderName>/<modelName> --alias <folderName> --host 127.0.0.1 --port 8080 -c 32768 -ngl 99 -np 1

	- -c 32768   context size: it must be the same for all models.
	- -ngl 99    offloads all layers to the GPUs. Check in the start-up log how many layers
	             are offloaded and, with nvidia-smi, that the three GPUs are in use.
	- -np 1      a single slot, so that the whole context belongs to one conversation.
	- The chat template is taken from the GGUF file: do not force it with --chat-template.
	- Sampling (--temp, --top-p, --top-k, ...): use the values recommended on the model card,
	  identical for baseline and GE, and write them down. `request_params` in logs/turns.jsonl
	  shows what Chat UI actually sends; whatever it does not send comes from these flags.
	- Prompt cache: it is enabled by default (the KV cache of the common prefix is reused
	  between turns). To disable it, so that every turn reprocesses the whole history, add
	  --no-cache-prompt. Decide it once for the whole experiment.
	- Optional, to make the split over the GPUs explicit: --split-mode layer --tensor-split 1,1,1
	- Reasoning models: the selection admits only models whose chat template can turn reasoning off.
	  Start them with reasoning disabled, using the switch of the template, and keep it identical for
	  baseline and GE. Check the frozen selection (`reasoning.interruttori`): for enable_thinking use
	  `--reasoning off` (recent builds; it sets enable_thinking=false) or
	  `--chat-template-kwargs '{"enable_thinking": false}'`; for thinking_budget use
	  `--reasoning-budget 0` or `--chat-template-kwargs '{"thinking_budget": 0}'`. Check the flag with
	  `./build/bin/llama-server --help` and the server log. Also check how the reasoning is returned
	  (separate field or inline in the text), because it affects the context sent at the following
	  turns and the logs.

	Check the server and its configuration:
	curl http://127.0.0.1:8080/props

4. Start the energy_api proxy
	uvicorn energy_api:app --host 127.0.0.1 --port 9000

	Optional environment variables (see README.md), for example:
	TRACKING_MODE=machine uvicorn energy_api:app --host 127.0.0.1 --port 9000

5. Start the Chat UI application, from the chat-ui directory
	npm run dev

6. Before each session: set the session metadata
	curl -X POST http://127.0.0.1:9000/experiment/session -H "Content-Type: application/json" \
	     -d '{"participant_id": "P01", "task_id": "T1", "condition": "GE", "model": "<model label>"}'

7. After each session: close it
	curl -X POST http://127.0.0.1:9000/experiment/session/end -H "Content-Type: application/json" \
	     -d '{"task_completed": false, "notes": "..."}'
